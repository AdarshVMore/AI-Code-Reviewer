The shortcuts baked into this diagram

Not bugs exactly — decisions made to ship, that the scalable version (part 2) exists to unwind.

Full repo re-index every time rag.service.ts

Every PR open/sync re-downloads the entire repo zip, re-chunks every file, re-embeds everything — regardless of how many files actually changed.

One vector index per repo Pinecone

Works fine at a handful of repos. Pinecone charges and rate-limits per index, so this doesn't hold as install count grows.

api-service imports worker-service deployment.controller.ts

The "apply fix" endpoints reach directly into worker-service's internal modules instead of going through the queue — the two services aren't actually independently deployable.

One Redis instance, three jobs Upstash

Queues and cache share the same instance with no replication. A cache eviction storm and a lost queue item are one incident away from each other.

Sequential Claude calls review.service.ts

Classify type → generate search query → main review → gif title, each one waits on the last, even where nothing downstream actually depends on it.

Free-tier sleep everywhere Render

All three backend processes cold-start after 15 idle minutes. The wake-ping between webhook and worker is a real fix for a real constraint — but it's a workaround, not a scaling strategy.
